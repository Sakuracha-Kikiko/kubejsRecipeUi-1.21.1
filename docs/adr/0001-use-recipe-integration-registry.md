# ADR 0001：使用配方集成注册表

日期：2026-07-31

## 状态

已采纳。

## 背景

当前每增加一个模组配方类型，都需要同时修改 `WorkstationType`、`RecipeEditorUi`、
`RecipeEditorSession`、`RecipeDefinition`、`KubeJsRecipeGenerator` 和 JEI 集成。
其中核心界面和代码生成器依赖覆盖全部工作站的 `switch`，容易遗漏分支，也让可选模组逻辑进入核心代码。

## 决策

采用增量注册式架构：

- 保留 `WorkstationType` 作为稳定的工作站类型标识。
- 每个配方集成通过注册表集中声明依赖模组、侧栏分组、校验器和代码生成器。
- 核心代码生成器只处理删除逻辑和 `ServerEvents.recipes` 外层包装。
- 客户端使用独立的面板注册表分派 LDLib2 面板，避免服务端公共代码加载客户端 UI 类。
- 模组专属参数通过 `RecipeSettings` 按类型保存，核心模型和 JEI 桥接无需增加固定字段。
- JEI 继续使用独立集成入口，后续再迁移为同样的贡献者注册方式。

## 结果

新增模组配方支持时，可以先增加一个集成类并注册工作站，不再修改核心代码生成器。
界面面板仍可逐步拆分，迁移过程不会改变已有配方脚本格式和玩家数据。

## 暂不处理

现有 LDLib2 面板构建方法仍集中在 `RecipeEditorUi`。第一阶段只迁移面板分派入口，后续可以按模组逐步拆分，
避免一次移动大量控件代码导致布局回归。
