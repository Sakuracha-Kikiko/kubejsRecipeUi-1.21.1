# KubeJS 事件编辑器设计

事件编辑器由配方界面左侧的命令方块图标切换，并与配方编辑器复用同一个 LDLib2 主界面，不再打开独立模态框。点击任一工作方块按钮会切回配方页面，JEI 填充配方时也会自动切回对应工作方块页面。事件目录从 `EventGroups.ALL` 动态读取，因此包含当前环境中所有 KubeJS 插件注册的事件。事件按 `Group.event` 排序，显示文本优先使用本模组翻译，缺少翻译的第三方事件回退到原始 ID。

界面包含事件下拉框、脚本端下拉框、可选目标 ID 和 JavaScript 代码编辑器。脚本端候选由事件的 `ScriptTypePredicate` 决定。目标输入框仅在事件支持或要求目标时显示，搜索输入框和候选下拉框各占独立一行；方块、物品、实体、维度、菜单、创造物品栏和注册表目标从当前游戏注册表读取，枚举目标使用固定候选，自由字符串和未知第三方目标保留手动输入。候选以“本地化名称（注册 ID）”显示，搜索同时匹配名称和 ID，生成代码仍只使用注册 ID。输入文字会过滤下拉候选，单次最多显示 200 项。为容纳独立候选行，代码预览区域适度压缩。选择事件会生成可编辑监听器骨架，用户可以重新生成、复制或写入。

事件页标题水平居中，顶部表单使用紧凑间距。事件方法下拉框从当前事件类型及其 KubeJS 接口继承的方法中读取脚本可见 API，排除内部生命周期方法和 `@HideFromJS` 方法。选择方法后只在回调中填入 `event.方法(...)`；当方法需要参数时，上一行以注释列出参数名称和类型，并为调用填充可编辑占位值。

写入通过现有 LDLib RPC 在服务端验证权限，并按启动端、服务端、客户端分别追加到 `startup_scripts`、`server_scripts`、`client_scripts` 下的 `generated_events.js`。事件脚本不使用共享外壳，每段监听器独立追加。多人服务器仍要求管理员权限。

验证继续采用 `gradlew build -x test` 和单客户端运行，不增加单元测试。
