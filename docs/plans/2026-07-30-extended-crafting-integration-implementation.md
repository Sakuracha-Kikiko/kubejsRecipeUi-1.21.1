# Extended Crafting 可选集成实施计划

## 第一步：依赖与工作站描述

- 在 Gradle 中加入 Blake's Mods Maven、Extended Crafting/Cucumber 版本和开发运行依赖。
- 在模组元数据中声明可选的 `extendedcrafting` 依赖。
- 扩展工作站描述，使图标、网格尺寸、所需模组和配方族可被统一查询。
- 验证：不启动游戏执行依赖解析和 Java 编译。

## 第二步：配方状态与生成器

- 为各 Extended Crafting 配方参数增加独立不可变模型。
- 扩展编辑会话，分别保存每个工作站的输入、输出和数值参数。
- 扩展配方校验与自动 ID 内容摘要。
- 生成符合 26.1 Codec 的 `event.custom` 代码，同时保留现有删除策略。
- 验证：对每个工作站生成一段预览并检查类型和必需字段。

## 第三步：LDLib2 工作站面板

- 只为已经加载所需模组的工作站创建侧栏按钮和面板。
- 为 3×3、5×5、7×7、9×9 扩展工作台增加紧凑网格，并扩大主编辑区。
- 增加组合合成、压缩机、末影合成器和通量合成器面板及专属数值字段。
- 复用槽位清空、右键原料设置、标签、替代材料、数据组件和输出数量功能。
- 验证：编译并检查所有面板元素 ID 唯一。

## 第四步：JEI 可选集成

- 在检测到 Extended Crafting 后注册八个 JEI 配方分类的转移处理器。
- 从上游接口读取阶级、尺寸、能量、功率、数量和时间。
- 将来源信息和配方内容传给 LDLib2 桥接元素。
- 验证：编译期类型检查，确认没有让 Extended Crafting 变成必需依赖。

## 第五步：资源与构建

- 添加中英文工作站名称、字段名称、提示和错误信息。
- 更新 README 的可选集成说明。
- 执行 UTF-8、JSON、Git diff 和完整 Gradle 构建检查。
- 不启动额外 Minecraft 客户端。
