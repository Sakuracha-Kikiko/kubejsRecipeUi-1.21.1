# Applied Energistics 2 配方编辑集成设计

## 目标与范围

当运行环境安装 `ae2` 时，工作台编辑器侧栏只增加一个 Applied Energistics 2 入口，并在属性检查器中通过下拉框切换充能器、压印器、物品转化和熵变处理四类配方。未安装 AE2 时不显示入口，通用编辑器代码不主动加载 AE2 类，模组仍可正常启动。首期覆盖 AE2 自带 JEI 面向玩家展示的四种主要配方，不包含物质炮弹药、存储元件拆解和合成单元转换等内部规则。

充能器使用单输入和单输出槽；压印器使用上、中、下三个输入槽，其中中间材料必需，并提供压合、压印模式；物品转化使用三个输入槽和一个输出槽，允许选择爆炸或流体条件；熵变处理不强制使用物品槽，而是编辑加热或冷却模式、方块或流体输入，以及方块、流体或掉落物输出。每一类工作站在会话中保存独立状态，切换类型不会清空已经填写的内容。

四类界面直接复刻 AE2 26.1 自带 JEI 分类，而不再混用机器容器界面。充能器使用 `130x50` 画布，输入 `(31,8)`、箭头 `(52,8)`、输出 `(81,8)`、手摇曲柄 `(3,30)`，并显示 `10 AE/t`。压印器使用 `97x64` 画布，直接读取 `ae2:textures/guis/jei.png` 中的背景切片，槽位为上方 `(1,1)`、中间 `(22,24)`、下方 `(1,47)`、输出 `(69,24)`，进度条位于 `(91,23)`。物品转化使用 `130x62` 画布，三个材料槽位于 `(6,6)`、`(6,24)`、`(6,42)`，条件槽 `(56,24)`、输出槽 `(106,24)`，两段箭头分别位于 `(25,23)` 和 `(76,23)`。熵变处理使用 `130x50` 画布，输入 `(29,15)`、箭头 `(53,14)`、输出 `(85,15)`，并同步显示冷热图标、能耗和鼠标操作说明。所有箭头、槽框、压印器背景与冷热图标均截取 AE2 自带 JEI 纹理；编辑器专用下拉框和资源 ID 字段统一放在 JEI 画布下方，动态文本和 JEI 回填不会推动槽位发生位移。

## 数据与生成

`WorkstationType` 为每个可选工作站保存所需模组 ID，统一通过 `ModList` 判断可用性，避免依赖枚举顺序判断 Extended Crafting。`Ae2RecipeSettings` 保存压印模式、转化条件、流体标签和熵变资源。`RecipeDefinition` 继续作为生成器唯一输入，但允许熵变配方没有物品输出，并使用熵变输出资源生成稳定 ID。

四类代码都使用 `event.custom({...}).id(...)`，序列化器分别为 `ae2:charger`、`ae2:inscriber`、`ae2:transform` 和 `ae2:entropy`。物品型材料继续支持标签、替代材料与数据组件；熵变资源 ID 在预览前校验 `namespace:path` 格式。删除配方仍支持 ID、类型、模组、分组、输入和输出，熵变的输入、输出删除条件直接读取资源 ID。

## JEI 与兼容性

AE2 专用 JEI 注册器只在检测到 `ae2` 后调用，并为四个 `AERecipeTypes` 注册编辑器转移处理器。转移时读取材料、输出、配方 ID、序列化器、来源模组以及配方对象中的压印模式、转化条件和熵变资源；流体信息不依赖 JEI 的物品槽。回填完成后同步会话、槽位、下拉框和文本字段。

项目以 `compileOnly` 编译 AE2 API，AE2 与 GuideME 只加入开发运行环境，模组元数据将 AE2 声明为版本范围 `[26.1,)` 的可选依赖。验证包括 Java 编译、完整构建、翻译键一致性、UTF-8、`git diff --check`，以及检查发布 JAR 不包含 AE2 类。
